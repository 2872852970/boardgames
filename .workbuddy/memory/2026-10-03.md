## 新增重力四子棋 + 游戏选择大厅（场景重构）

### 成果
- 第二个棋类 **Connect Four**（`games/connect4/`，key=`connect4`）：规则 / 评估 / 视图全套
- **弹跳下落动画**（`ui/animation.py` 的 `BounceTween`，物理积分而非补间曲线）
- **场景架构**（`ui/scene.py` + `lobby.py` + `match_scene.py`），大厅 ↔ 对局可切换
- **侧栏参数按棋类隔离**（`ParamSpec.games` 字段）
- 测试 138 → 233 项，ruff 全清

### 关键实现决策

**`Game.settings_map` 取代硬编码构造参数**
`session._build_game` 原先给构造器硬传 `size=/walls=/first_player=` 并 `except TypeError`
兜底 —— 实测会**静默丢弃** `first_player=p2`，且回退到注册表的**共享单例**（跨对局污染）。
改成各 `Game` 自己声明 `settings_map: ClassVar[Mapping[str,str]]`（纯 ClassVar，
core 不能 import settings，`settings.store` 已依赖 `ai.engine`，反向 import 会成环）。

**`ParamSpec.games` 解决"参数跨棋类泄漏"**
原来 `board_size` / `walls_per_player` / 墙棋专属权重会在四子棋侧栏里也露出来。
加 `games: tuple[str,...] = ()`，`Sidebar._spec_applicable` 首行过滤。`Sidebar.__init__` 收
`game_key`，另加 `set_game()`。**对持久化零影响**（`Settings` 从 `default_values()` 起填，
旧配置缺新键自动取默认；`load()` 从不校验 `schema_version`）。

**场景重构用转发 property 保住 205 处测试访问**
`tests/ui/*.py` 有 205 处 `window.xxx`（`_handle_events` 44 / `session` 35 / `_update` 27 …）。
Python 属性解析不穿透到 scene，所以「把逻辑搬进 MatchScene 让测试改访问」会碎掉全部 UI 测试。
做法：`MatchScene` 持状态，`GameWindow` 暴露同名 property 转发；
**`start_scene` 默认 `"match"`**（不是 lobby）让 `make_window()` 零改动，
产品入口 `app.main` 显式传 `start_scene="lobby"`。默认反直觉，已在 docstring 注明。

**大厅卡片数据来自 `Game` 的 ClassVar**
`tagline` / `summary` / `rules` / `icon` 四项，大厅遍历 `registry.all_games()` 自动生成 ——
接第三个棋类大厅零改动。⚠️ `all_games()` 返回共享单例，**绝不能**在 lobby 里调
`initial_state()` 等有副作用的方法。

### 踩过的坑（都已加回归测试）

1. **`scan_win` 双向延伸必须相加** —— 最初写成「正反两个方向各自独立计数再判断 >=4」，
   于是"落点补上横四中间那一子"（`X.XX` → 投中间变 `XXXX`）**永远判不出胜负**。
   正确做法：`total` 跨两侧累加。
2. **`winner` 字段名会遮蔽 ABC 方法** —— `State.winner()` 是抽象方法，
   同名字段会让 `minimax` 里 `state.winner()` 拿到非可调用对象。字段叫 **`winner_player`**。
   **而且要用玩家索引（0/1）而不是 `cells` 里的棋子值（1/2）** —— 引擎会拿
   `state.winner()` 直接和玩家索引比较，用棋子值会让符号整个反过来
   （实测 minimax 深度 1~6 全部找不到"三连直接赢"这种必胜手）。
3. **四子棋不能有 tempo（节奏）项** —— 墙棋里"轮到谁走"有先后优势，四子棋没有。
   加这一项会破坏 `evaluate(s,0) == -evaluate(s,1)`，minimax 在双方都不占便宜的局面里乱选。
   同理 `w_threat` / `w_block` 必须合并成一个权重，否则不对称。
4. **弹跳积分必须固定子步（1/240s）** —— 朴素半隐式欧拉在 `dt=33ms`（掉帧）时反弹
   440 次、持续 4 秒、**锁死输入**。`window.run()` 里 `dt_ms = min(dt_ms, 100)` 的上限
   意味着切后台回来必踩。重力还要按落差归一化（`g ∝ drop_px`），否则底部落子 458ms、
   顶部 1458ms。
5. **`BounceTween` 的超时兜底必须在子步循环之外** —— 若棋子一直悬在半空、始终碰不到
   `drop_px`，落在触底分支里的超时判定永远不触发，会**永远播下去并锁死输入**。
6. **`minimax` 的 `include_walls=ply < wall_depth` 必须完全忽略** —— 那是为墙棋的墙分支设计的，
   四子棋若把它当"裁剪着法"，深度 ≥2 的节点只剩 ≤1 个着法，棋力直接崩却查不出原因。
7. **`PLACEMENT_MODE_KEY` 别名** —— `ui/window.py` 原先模块级硬 import
   `games.quoridor.view.WALL_MODE_KEY`（框架最脏的耦合）。改到 `ui/board_view.py`，
   quoridor 保留 `WALL_MODE_KEY = PLACEMENT_MODE_KEY` 同值别名 → 8 个引用它的测试零改动。
8. **`Esc` 语义变更是唯一预期失败** —— `test_escape_leaves_wall_mode_before_quitting`
   原本断言 2nd Esc 退出程序，现在是回大厅。这是语义变更导致的**预期修改**，不是回归。
9. **测试文件重名冲突** —— pytest rootdir 模式下 `tests/games/*/test_win.py` 会撞
   （`import file mismatch`）。四子棋的测试统一加 `c4_` 前缀。
10. **手写棋盘图字符串极易抄错** —— 造局面优先用 `conftest.make_at(cols, rows, {(col,row): 值})`，
    按坐标写、其余自动填 0 或指定 fill，能自动保证重力（不会"忘了补齐某一列"）。

### 待办：MCTS 棋力已实测，没问题

预判的「MCTS 在四子棋上可能退化」**实测不成立**：

- 必胜（投中即赢）与必防（堵对手三连）：minimax / mcts 全部抓住（random 引擎抓不住，符合预期）
- minimax(depth 6) vs mcts(4000 iter) 各 8 局：**4 胜 4 胜 0 平**，约 7.4s/局

结论：`ROLLOUT_VALUE_SCALE = 600` 虽然是为墙棋调的（墙棋 `w_path=100`/步，评估分轻松上百），
但四子棋的 rollout 策略本身够强（贪心 + 威胁优先 + 中心加权随机），回报仍有足够区分度。
**不需要调权重，也不要动 `ROLLOUT_VALUE_SCALE`。**

`c4_test_heuristic.py` 里那条 `test_evaluate_magnitude_is_reasonable`（守住评估分中位数 > 5）
继续留着当护栏。

### 遗留的待观察项

- 四子棋的评估分中位数（约几十）确实远低于墙棋。`test_evaluate_magnitude_is_reasonable`
  只守住下限（> 5），没设上限 —— 如果将来发现 MCTS 在四子棋上变弱，优先怀疑这里。

## 修复：四子棋重力反了 + 落子预览没对齐（用户截图反馈）

用户截图里棋子全堆在棋盘**顶部**、预览棋子浮在槽位上方，还带出一个"已落 33 子"。

### 根因（都是真 bug，四子棋独有的三处 + 一处通用）

1. **行号方向翻反了**（棋盘上下颠倒）
   局面里 `row == 0` 是**最底行**（重力压向 0），屏幕 y 却向下增大。
   `cell_center` 直接拿 `row` 当屏幕行用 → 整盘倒挂、棋子堆顶。
   修法：**只在一处翻** —— 新增 `Connect4View.screen_row(row) = rows-1-row`，
   `cell_center` 内部用它；其它地方一律只用局面坐标。**两处各翻一次 = 没翻。**
2. **`BounceTween.offset()` 符号写反**（"重力方向反了"的动画版）
   `_y` 存的是**已经落下的距离**（0 → `drop_px`），偏移应写 `_y - drop_px`，
   原实现是 `-_y`：起点恰好落在槽位上，然后一路**往上飞**出棋盘、悬在半空，
   动画结束时再瞬间落下。同时退化分支（`duration<=0`）要把 `_y` 置成 `drop_px` 才等于"已静止"。
3. **落子预览给了 0.12 格的纵向偏移** —— 想画成"浮在落点上方"，看着就是没对准。
   现在预览与圆窝**同心同径**（都是 `cell_center` + `socket_radius`），并抽出
   `ghost_center()` 方便直接断言。
4. **棋子调色板索引写成棋子值（+1）** —— `theme.PLAYER_COLORS` 只有 2 项（玩家号 0/1），
   `PLAYER_COLORS[state.current + 1]` 在**玩家 2 悬停时越界崩**（`_draw_ghost`），
   `PLAYER_COLORS[winner_player + 1]` 在**玩家 2 赢棋时越界崩**（`_draw_win_line`）。
   之前 233 项测试没覆盖"悬停着画一帧"和"玩家 2 赢"这两个组合，所以一直没暴露。
5. **`Connect4State.count_pieces()` 用"总格数 − 已落子数"算对手** —— 那是**空格数**，
   空盘 7×6 会报"对手已落 42 子"。正确写法 `heights_total() - p0`。

### 顺手改掉的两处观感问题

- **下落改为"从棋盘上沿进场"**：`drop_px_for(row)`，落点越低掉得越远
  （真棋具就是从顶口投子）。旧实现是固定 2 格落差，翻转后会让棋子**在棋盘中间凭空出现**。
- **高亮跟"最后一手"走**（不再给当前行动方的**所有**棋子加光环 —— 颜色本身已经说明归属，
  一片光环只是噪声）。
- **正在下落的那枚最后画**：它要穿过已有棋子，先画会被沿途棋子盖住，像钻进棋盘里消失。

### 测试（233 → 244 项）

- `tests/ui/test_bounce.py`：`offset` 改为"起点 -drop、落定 0"，新增第一段下落**单调向下**（触底正好归零）
- `tests/ui/test_connect4_view.py`：新增按**像素**判重力（落子在底行那格必须是棋子色）、
  预览不越出槽位圆（在 `radius+2` 处比对有无预览两帧）、预览颜色随行棋方、
  玩家 2 赢棋高亮、`drop_px` 随行号变大
- `tests/games/connect4/c4_test_counts.py`：`count_pieces` 的回归（空盘必须是 0/0）

**教训：渲染类的 bug 必须用"画一帧再取像素"的测试锁住**，光断言数据结构（`state.at`）
永远抓不到"上下颠倒""差半个格"这类问题。

## 新增第三个棋类：大力士棋（Abalone）+ 全量接入

### 成果
- 第三个棋类 **大力士棋**（`games/abalone/`，key=`abalone`，icon=`hex`）：几何 / 三种布局 /
  状态 / 着法 / 规则（含推挤） / 评估 / 六边形视图全套
- **三种官方起始布局**可侧栏切换（standard / belgian_daisy / german_daisy，即切即开新局）
- 交互 = **两段式点击**（点棋子选组 → 点目标格出招），不做拖拽
- 测试 422 项全绿（其中大力士棋相关 182 项），ruff All checks passed

### 关键实现决策
- **几何**：pointy-top + axial `(q,r)`，半径 4 = 61 格，`max(|q|,|r|,|q+r|) <= 4`；
  行宽 5-6-7-8-9-8-7-6-5；`LINES`(285) 预生成 2/3 连片段，单子单独扫 6 方向（否则单子被生成三遍）。
  反解 cube round **必须 half-up**（Python `round()` 是 banker's rounding，会吸到隔壁格）。
- **评估反对称由构造成立**（每项 `w*(f(me)-f(opp))`），**不加 tempo 项**；
  `w_abalone_danger` 用 ring 的平方（线性项与中心项信息重复）。实测 `|score| ≲ 725`。
- **`out[p]` = p 推出的子数**（不是 p 自己掉的），`is_terminal` 与 `winner` 直接合拍。

### 这一轮抓出来的四个真 bug（都不是测试写错）
1. **`AbaloneMove.shifted()` 返回源格 → 滑行动画完全没播**（棋子瞬移）。
   视图画的是"走完之后"的局面，必须用**目标格**。改成 `destinations()`。
   —— 又是"渲染 bug 只能靠画一帧发现"，但这次连数据结构断言都看不出来，得看动画。
2. **`max_branch` 截断把推挤类着法系统性砍光**：生成顺序是"先单子、后连子"，
   而 MCTS 传 `order=False` → 实测连"白送一枚挤出"都进不了搜索树。
   改为 **截断隐含排序**（只要会截断就先按 `_order_key` 排）。
3. **`is_terminal` 漏了"行棋方无处可走"**：稀疏局面下 MCTS rollout 一直索取着法直到
   抛 `RuntimeError`（`AIWorker._run` 吞掉异常 → "AI 突然不下棋"）。
   加一条用 `marble_count()` 实现的防御性判据（**不能**在这里调 `legal_moves`，会慢一倍）。
4. **提示胶囊固定 210px 会把长文案从两侧截掉**（看着像文字跑到屏幕外）。
   改为按 `font.size(label)` 自适应宽度。

### 顺手修掉的观感问题
- 大力士棋的 `hover_hint` 文案缩短到 ≤20 汉字
- `MatchScene._player_details` 加 abalone 分支（原样会显示成"墙 0"）
- 大厅卡片图标新增 `"hex"`（20 个圆点组成的小六边形 + 中间三格画"2 推 1"）

### 实测锚定值
- 开局合法着法数 **standard 44 / belgian_daisy 52 / german_daisy 80**
- 自对弈收敛：minimax depth4 × 400ms vs mcts 400ms，三种布局 49~67 手全分胜负；
  默认参数（mcts 1200ms / max_branch 8）单局 86 手收敛，子数守恒 8+11+3+6=28 ✓

`MEMORY.md` 已涨到 18.7k 字符、超出注入上限被截断。拆成
`MEMORY.md`（3.4k，只放最高频致命坑 + 索引）+ `details/{architecture,ai,ui,quoridor,connect4,abalone}.md`。

## 新增第四个棋类：昆虫棋（Hive）+ 通用摄像机（Camera）

### 成果
- `games/hive/`：geometry（pointy-top 六边形 + 滑动门）/ pieces / state（**无边界 + 叠层 + 推导手牌**）
  / move（PlaceMove / MoveMove / PillbugMove / **PassMove**）/ rules / heuristic / view / assets
- 棋子：基础 5 种（蜂后／甲虫／蚱蜢／蜘蛛／兵蚁）+ 官方扩展 3 种（瓢虫／蚊子／鼠妇，侧栏开关默认关）
- `ui/camera.py`：**框架级通用摄像机**（平移 / 缩放 / 自动适配），`MatchScene` 用 `hasattr` 探测接入，
  另外三个棋类一行未改
- 素材：OpenMoji（CC0）真图标 + 运行时按玩家色着色 + 程序绘制兜底（`scripts/fetch_hive_assets.py`）
- 测试 422 → **623 项**，ruff 全清

### 关键实现决策
1. **无边界棋盘在状态层就是 `Pos -> 栈` 的映射**，不是定长数组。手牌由"配额 − 盘上数量"**推导**，
   从根上杜绝"手牌与盘面不同步"这一整类 bug。
2. **`PassMove` 是昆虫棋独有且必需**：规则规定一枚棋都动不了时必须 pass。四个引擎在
   "只能 pass 的局面"都必须交 `PassMove` 而不是 `None`（新增 AI 契约测试锁死）。
3. **摄像机做成框架能力**（用户的第四个选择项）：`screen = world * scale + offset`，
   `fit(..., max_scale=)` 有软上限（开局包围盒小，不设上限会把一枚棋放大到铺满画布）。
   视图可选钩子（`camera_viewport` / `auto_fit_camera` / `hud_inset` / `idle_hint` …）全是
   `hasattr` 探测 —— 加钩子不影响老棋类。
4. **点击 / 拖拽由 `CameraController` 裁决**（按下→扣住→松手按累计位移判，`DRAG_SLOP=4`），
   视图只收到"干净点击"；拖拽画布的松手事件被吞掉，不会误落子。
5. **两段式交互**：手牌卡 → 绿点；点己方棋 → 绿点；鼠妇多一步"点可搬的棋 → 橙点"。

### 这一轮抓出来的真 bug
1. **`PillbugMove.destinations()` 报了没动的格子** —— 鼠妇搬运时 `dest == src`（它自己不挪窝），
   把 `dest` 一并报出去会点亮错误的格子。改成只报 `carried_dest`，`_OrderContext.key()` 同步用 `carried_dest`。
2. **`_dedup()` 只按 `dest` 去重** → 鼠妇搬运的八手 `dest` 全是同一格，被合并成一手
   （"点哪都只出一种搬运"）。改为按 `(dest,)` 或 `(dest, carried, carried_dest)` 复合键去重。
3. **手牌条左侧的「手牌」标签被卡片整块盖住** —— 标签和卡片同高，而卡片是不透明底且后画。
   加 `HAND_LABEL_W = 30` 给标签留专属窄条，卡片从它右边开始排。
4. **`--hover` 截图在没有交互权的模式下拍不到落点**：视图的落点绘制挂在 `interactive` 上，
   而 eve（暂停）时 `interactive=False`。截图命令要显式 `--mode pvp`。
   （`config/settings.json` 里若存了 `mode=eve`，默认的截图命令会拍到"什么都没有"的画面。）

### 实测锚定值（`.workbuddy/artifacts/bench_hive.py`）
- 分支因子随蜂巢生长：ply1 **5** → ply10 51 → ply20 **101** → ply40 77
- `legal_moves` **0.18ms**（约 80 着法）；Minimax d4 b16 **141ms**、d6 b16 1206ms
- MCTS 吞吐 **~83 nps**（对比 quoridor 593 / abalone 179 / connect4 2088）——
  rollout 每步都要生成长着法表，是四个棋类里最慢的。**昆虫棋建议用 Minimax**
  （d4~6、候选上限 16~32），MCTS 只适合当陪练。
- 自对弈收敛：MCTS400 × Minimax d3 三局 35 / 20（和） / 52 手；主循环里跑 eve
  （AI 线程 + 动画 + 绘制）17 手正常分胜负，结果文案正确。

### 待办 / 未做
- P8 只做了压测与默认值确认，**没有改任何全局默认**（`minimax_max_branch` 等是共享的，
  改默认会连带动墙棋）。调参建议写进了 README。

## 第二轮返工（用户实机截图反馈，8 项）

用户贴了一张实机截图，报了 8 件事；其中"不同队伍的棋子不好区分了"是配色返工的关键一击。

### 1. 开局必须先滚轮才能落子（真 bug）
`MatchScene._auto_fit_camera()` 在 `auto_fit` 为真时**每帧**调 `_refit_camera()`，
而后者第一行是 `self._cam.cancel()`。主循环是"先派发事件、再 `update()`"，
左键按下与松手天然落在相邻两帧：
- 第 N 帧：`_handle_events()` 记下按下 → `_update()` 立刻 cancel 掉
- 第 N+1 帧：松手时看到"没按下过" → 什么都不做 → **点击被静默吞掉**

滚轮会把 `auto_fit` 置假 → 之后才不再每帧清手势，所以表现就是"必须先滚一下"。
修：`_auto_fit_camera()` 里 `if self._cam.pressed: return`；`_refit_camera()` 不再 cancel；
`_fit_camera()`（F 键）显式 cancel。

### 2. 镜头有两个"不许乱动"的规则（同一个 bug 的两条修）
- **内容还看得见就别动**：`_auto_fit_camera()` 现在先问视图要 `world_bounds(state)`，
  `camera.contains(bounds)` 为真就直接返回。否则昆虫棋每落一子包围盒变大一点，
  镜头跟着缩一点 —— 玩家看到"我刚落完子画面抖了一下"。
  （实测：40 手对局镜头只在第 30 手变过一次，1.000 → 0.918。）
- **`AUTO_FIT_MAX_SCALE = 1.0`（只缩不放）**：曾经为了"大屏好看"给到 2.5，
  结果开局空盘被放成 **201%** 贴满画布。100% 时一枚棋直径约 70px，够点够看。
  那"分辨率自适应"体现在**装不下时缩**：同一局面 1600×900 → 100%、1024×768 → 86%。

## 第二批：规则说明界面、精简大厅卡片、无边框窗口（下午）

### 7. 「无头」的真实含义 = 去掉 pygame 系统标题栏
用户澄清："无头是指无pygame标题头"。之前我实现成了"没有显示器时切 dummy 驱动跑"，
方向错了。现在拆成两个独立开关：

- `--frameless`（别名 `--headless`，也对应 `GameWindow(frameless=True)`）：
  `pygame.NOFRAME` **窗口照常显示**，程序自绘一条标题栏（新文件 `ui/chrome.py`）：
  标题跟随场景 + `—` 最小化（`display.iconify()`）+ `□` 全屏（`NOFRAME|FULLSCREEN`，
  无边框没有边可贴，最大化就等于全屏）+ `×` 关闭 + 空白处拖动
  （Windows 借 `WM_NCLBUTTONDOWN`+`HTCAPTION`，其他平台降级为拖不动，不抛异常）。
- `--offscreen`：SDL dummy 驱动，**完全不显示窗口**，给 CI / 跑批 / 截图用
  （老的 `--headless` 截图命令全部改成它）。

坑（都写进 MEMORY.md 了）：
- 场景必须用 `window.content_rect`（顶部让出 `TITLEBAR_H = 34`），否则卡片/棋盘被压住；
- `TitleBar.handle_event` 只吃落在自己那一条里的鼠标事件，其余 `return False` 放行；
- **`self.titlebar` 必须在 `_open_screen()` 之前置好** —— `_flags()` 要读它，
  否则 `AttributeError`（改完当场炸了 21 个窗口冒烟用例）。

### 8. 大厅卡片精简 + 图标重做成「局面切片」
卡片原先塞了图标 + 名称 + tagline + 折行简介 + 3 条规则要点。现在只留
**图标 + 名称 + 副标题 + 一行简介**，卡片底部一个「规则说明」按钮。
卡片变矮（`CARD_MIN_H/MAX_H = 236/300`），`ICON_H = 96`。

图标改成"一局棋里的一个瞬间"，四个都用玩家色表达双方：
- 墙棋：己子被墙挡在正前方 → **直角折线**（`(x2, y4-9)→(x2, turn_y)→(x0, turn_y)→(x0, y1-2)`）
  绕过去，上下两条底线是双方目标；
- 四子棋：底行三连 + 第 4 格**虚线落点预览**（不是悬在盘上方的一枚子 —— 用户嫌突兀），
  最左一列两子叠着表达重力；
- 大力士棋：**残局** —— 盘上 6+4 枚，盘外虚线边界外躺着 3 枚半透明的已出局子，
  中央三推一顶着箭头；
- 昆虫棋：蜂后被围五面 + 缺口绿色虚线 + 外围虚线格表示无边界。

`ui/_marble()` 的描边改成**按半径取比例**（约 1/4）而不是写死 2px，
否则 5px 半径的小棋子会被描边挤成一个点。
