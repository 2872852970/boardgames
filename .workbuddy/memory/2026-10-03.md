# 2026-10-03

## 新增重力四子棋 + 游戏选择大厅（场景重构）

### 成果
- 第二个棋类 **Connect Four**（`games/connect4/`，key=`connect4`）：规则 / 评估 / 视图全套
- **弹跳下落动画**（`ui/animation.py` 的 `BounceTween`，物理积分而非补间曲线）
- **场景架构**（`ui/scene.py` + `lobby.py` + `match_scene.py`），大厅 ↔ 对局可切换
- **侧栏参数按棋类隔离**（`ParamSpec.games` 字段）
- 测试 138 → 233 项，ruff 全清

### 关键实现决策

**`Game.settings_map` 取代硬编码构造参数**
`session._build_game` 原先给构造器硬传 `size=/walls=/first_player=` 并 `except TypeError`
兜底 —— 实测会**静默丢弃** `first_player=p2`，且回退到注册表的**共享单例**（跨对局污染）。
改成各 `Game` 自己声明 `settings_map: ClassVar[Mapping[str,str]]`（纯 ClassVar，
core 不能 import settings，`settings.store` 已依赖 `ai.engine`，反向 import 会成环）。

**`ParamSpec.games` 解决"参数跨棋类泄漏"**
原来 `board_size` / `walls_per_player` / 墙棋专属权重会在四子棋侧栏里也露出来。
加 `games: tuple[str,...] = ()`，`Sidebar._spec_applicable` 首行过滤。`Sidebar.__init__` 收
`game_key`，另加 `set_game()`。**对持久化零影响**（`Settings` 从 `default_values()` 起填，
旧配置缺新键自动取默认；`load()` 从不校验 `schema_version`）。

**场景重构用转发 property 保住 205 处测试访问**
`tests/ui/*.py` 有 205 处 `window.xxx`（`_handle_events` 44 / `session` 35 / `_update` 27 …）。
Python 属性解析不穿透到 scene，所以「把逻辑搬进 MatchScene 让测试改访问」会碎掉全部 UI 测试。
做法：`MatchScene` 持状态，`GameWindow` 暴露同名 property 转发；
**`start_scene` 默认 `"match"`**（不是 lobby）让 `make_window()` 零改动，
产品入口 `app.main` 显式传 `start_scene="lobby"`。默认反直觉，已在 docstring 注明。

**大厅卡片数据来自 `Game` 的 ClassVar**
`tagline` / `summary` / `rules` / `icon` 四项，大厅遍历 `registry.all_games()` 自动生成 ——
接第三个棋类大厅零改动。⚠️ `all_games()` 返回共享单例，**绝不能**在 lobby 里调
`initial_state()` 等有副作用的方法。

### 踩过的坑（都已加回归测试）

1. **`scan_win` 双向延伸必须相加** —— 最初写成「正反两个方向各自独立计数再判断 >=4」，
   于是"落点补上横四中间那一子"（`X.XX` → 投中间变 `XXXX`）**永远判不出胜负**。
   正确做法：`total` 跨两侧累加。
2. **`winner` 字段名会遮蔽 ABC 方法** —— `State.winner()` 是抽象方法，
   同名字段会让 `minimax` 里 `state.winner()` 拿到非可调用对象。字段叫 **`winner_player`**。
   **而且要用玩家索引（0/1）而不是 `cells` 里的棋子值（1/2）** —— 引擎会拿
   `state.winner()` 直接和玩家索引比较，用棋子值会让符号整个反过来
   （实测 minimax 深度 1~6 全部找不到"三连直接赢"这种必胜手）。
3. **四子棋不能有 tempo（节奏）项** —— 墙棋里"轮到谁走"有先后优势，四子棋没有。
   加这一项会破坏 `evaluate(s,0) == -evaluate(s,1)`，minimax 在双方都不占便宜的局面里乱选。
   同理 `w_threat` / `w_block` 必须合并成一个权重，否则不对称。
4. **弹跳积分必须固定子步（1/240s）** —— 朴素半隐式欧拉在 `dt=33ms`（掉帧）时反弹
   440 次、持续 4 秒、**锁死输入**。`window.run()` 里 `dt_ms = min(dt_ms, 100)` 的上限
   意味着切后台回来必踩。重力还要按落差归一化（`g ∝ drop_px`），否则底部落子 458ms、
   顶部 1458ms。
5. **`BounceTween` 的超时兜底必须在子步循环之外** —— 若棋子一直悬在半空、始终碰不到
   `drop_px`，落在触底分支里的超时判定永远不触发，会**永远播下去并锁死输入**。
6. **`minimax` 的 `include_walls=ply < wall_depth` 必须完全忽略** —— 那是为墙棋的墙分支设计的，
   四子棋若把它当"裁剪着法"，深度 ≥2 的节点只剩 ≤1 个着法，棋力直接崩却查不出原因。
7. **`PLACEMENT_MODE_KEY` 别名** —— `ui/window.py` 原先模块级硬 import
   `games.quoridor.view.WALL_MODE_KEY`（框架最脏的耦合）。改到 `ui/board_view.py`，
   quoridor 保留 `WALL_MODE_KEY = PLACEMENT_MODE_KEY` 同值别名 → 8 个引用它的测试零改动。
8. **`Esc` 语义变更是唯一预期失败** —— `test_escape_leaves_wall_mode_before_quitting`
   原本断言 2nd Esc 退出程序，现在是回大厅。这是语义变更导致的**预期修改**，不是回归。
9. **测试文件重名冲突** —— pytest rootdir 模式下 `tests/games/*/test_win.py` 会撞
   （`import file mismatch`）。四子棋的测试统一加 `c4_` 前缀。
10. **手写棋盘图字符串极易抄错** —— 造局面优先用 `conftest.make_at(cols, rows, {(col,row): 值})`，
    按坐标写、其余自动填 0 或指定 fill，能自动保证重力（不会"忘了补齐某一列"）。

### 待办：MCTS 棋力已实测，没问题

预判的「MCTS 在四子棋上可能退化」**实测不成立**：

- 必胜（投中即赢）与必防（堵对手三连）：minimax / mcts 全部抓住（random 引擎抓不住，符合预期）
- minimax(depth 6) vs mcts(4000 iter) 各 8 局：**4 胜 4 胜 0 平**，约 7.4s/局

结论：`ROLLOUT_VALUE_SCALE = 600` 虽然是为墙棋调的（墙棋 `w_path=100`/步，评估分轻松上百），
但四子棋的 rollout 策略本身够强（贪心 + 威胁优先 + 中心加权随机），回报仍有足够区分度。
**不需要调权重，也不要动 `ROLLOUT_VALUE_SCALE`。**

`c4_test_heuristic.py` 里那条 `test_evaluate_magnitude_is_reasonable`（守住评估分中位数 > 5）
继续留着当护栏。
