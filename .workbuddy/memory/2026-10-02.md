# 2026-10-02

## 从零搭建「棋类游戏」项目（首个游戏：步步为营 / Quoridor）

用 `uv` + Python 3.13 + `pygame-ce` 2.5.8 建了可扩展棋类游戏框架，交付完整可运行项目。
工作区原本是空目录。

### 交付内容

- `core/`：游戏无关抽象（`Move` / `State` / `Game[S,M]` / `SearchOptions` /`GameRegistry`）。
  `Game` 只要求 6 个方法：`initial_state` / `legal_moves` / `is_legal` / `apply` / `evaluate` / `rollout_move`。
- `games/quoridor/`：`geometry`（锚点↔边派生、BFS、目标距离场）/ `state` / `move` / `rules` / `heuristic` / `view`。
- `ai/`：`engine`（统一接口）/ `minimax`（负极大值+Alpha-Beta+迭代加深+Zobrist 置换表）/
  `mcts`（UCT+惰性展开+距离场 rollout）/ `tt` / `worker`（后台线程+取消+过期结果丢弃）/ `random_ai`。
- `controller/session.py`：模式解析（pvp/pve/eve）、悔棋、AI 调度。
- `settings/`：`ParamSpec` 驱动侧栏与持久化（JSON 原子写、越界裁剪、未知键丢弃、`set_volatile` 不落盘）。
- `ui/`：theme / fonts / render / animation / `board_view` 协议 / 6 个自绘控件 / sidebar / window。
- 测试 102 项（规则 41+ / AI 契约 / 参数 / 无头 UI 冒烟 10 项，用 SDL dummy 驱动）。
- `scripts/benchmark_ai.py`：性能与强度基准。
- `--screenshot` / `--demo N` / `--headless` CLI，用于生成验证截图。

### 关键决策

- 严格标准墙规则：禁重叠 + **禁交叉**（同锚点横竖墙成「十」字非法），端点相接的 L/T 形合法。
  用 `QuoridorGame(allow_wall_crossing=True)` 可放开。
- 棋盘渲染不做通用化，只做**可插拔**；侧栏/控件/AI 调度/悔棋共享。
- AI 用线程而非进程（接口只传可序列化数据，将来换 `multiprocessing` 成本低）。
- 悔棋用人机模式"回退到轮到人类"的语义（通常 2 步）。

### 踩过并修掉的坑（都是真 bug）

1. **MCTS 最终选步用了 `child.mean`**，但子节点的 mean 是**子节点行动方**视角 → 等于专挑对己方最差的着法。
   表现为对随机对手 0/6、对局全部 300 步不收敛。必须按 `node.player == root_player` 翻符号。
2. **rollout 用曼哈顿距离贪心会来回振荡**（无路可进时随机乱走，下一步又走回来），
   棋局永远打不完、MCTS 每次模拟都撞深度上限。改用**目标距离场**（多源 BFS，`lru_cache` 缓存）
   后 rollout 单调推进，8/8 胜随机、对局 15~39 步收敛。已加回归测试。
3. **放墙校验的 BFS 优化**：先用"双方最短路径的边集合"做前置判断——
   墙不阻断我方当前路径 ⇒ 必然仍连通（免 BFS）；不阻断对手路径 ⇒ 增量恒为 0（免 BFS）。
   `all_legal_walls` 从 10.45ms → 1.83ms，MCTS 迭代数翻 4 倍。
4. **搜索状态曾挂在引擎单例上**（`self.nodes`/`self._root_player`）→ 取消后立刻重开新搜索会串味。
   改成每次搜索一个独立 `_MinimaxRun` / `_MCTSRun`，引擎对象无状态。
5. **`ViewState.placing` 与 `QuoridorView.placing` 重复**导致放墙点击失效。统一到 `ViewState`。
6. **视图里重复实现了一份走法生成** → 高亮落点会与真实合法着法分叉。改为直接调 `game.pawn_moves_for`。
7. **折叠分组会把头部的模式控件也设成 `visible=False`** → 模式开关消失。头部控件不进分组列表。
8. **`▾/▸`（U+25BE/25B8）在微软雅黑里缺字变豆腐块**，换用 `▼/▶`。
9. **命令行覆盖会被退出时的保存写进配置文件** → 加了 `Settings.set_volatile()`。

## 第二轮：用户反馈的三个 BUG（已修 + 已加回归测试）

用户截图反馈：界面显示不全、AI 搜索时右侧"思考中"频繁闪烁、鼠标划过下拉菜单就反复抖动。

1. **分组标题折叠不判断事件类型**（`ui/sidebar.py`）：原来 `if header.collidepoint(mouse)`
   对**任何事件**都翻转 `section.expanded`，鼠标一划过标题就每帧翻一次，
   连带标题下方的下拉菜单一起疯狂显示/消失。
   → 改成只在 `MOUSEBUTTONDOWN + button==1` 时折叠。
2. **`Session.is_thinking()` 漏了 `_pending_move`**（`controller/session.py`）：
   AI 结果已返回、`ai_delay_ms` 落子停顿还没过完时 `is_thinking()` 返回 False，
   主循环每帧重新 `start_thinking()` → 搜索被反复重开，状态栏"思考中"闪烁，
   而且 AI **永远不落子**（`_ready_at` 每次重启都被推后）。
   → `is_thinking()` 纳入 `_pending_move`；结果到达时不再推后 `_ready_at`。
   这个 bug 只有在 `ai_delay_ms > AI 思考耗时` 时才出现，所以之前的测试（`ai_delay_ms=0`）没抓到。
3. **窗口尺寸不裁剪到屏幕**：1180×780 在小屏/高 DPI 下超出桌面，底部"新局/悔棋/认输"被裁掉。
   → 新增 `ui.window.choose_window_size()`（按桌面 94%×90% 裁剪，下限 760×560，
   且绝不超过桌面）；侧栏宽度按窗口宽度自适应收窄（372 → 316）。
   新增 `--window WxH` 便于强制尺寸调试布局。

回归测试在 `tests/ui/test_regressions.py`（已用"临时回退修复"验证过确实能失败）。

## 第三轮：交互重构 + 精简 UI + git（用户反馈）

用户要求：修滑块 bug、UI 按模式精简、放墙改成全程鼠标、启用 git。

1. **滑块不点击也跟着鼠标动**（`ui/widgets/controls.py`）：
   根因是 `Sidebar.handle_event` 只在鼠标位于侧栏内时才把事件派发给控件，
   于是**在侧栏外松开左键**时 `MOUSEBUTTONUP` 送不到滑块，`_dragging` 永久卡在 True，
   之后不按键鼠标一划过就改数值。
   → ① `MOUSEBUTTONUP` 无条件派发；② `Slider.update` 里用 `pygame.mouse.get_pressed()`
   兜底解除拖拽（取不到状态时保持不动，避免误清）。
2. **侧栏按模式精简**（`ui/sidebar.py` + `settings/schema.py`）：
   `ParamSpec` 新增 `needs_ai` / `needs_engine`；侧栏按 `status.player_types` 解析出
   "实际参战的引擎集合"，据此过滤分组与单个参数。
   双人对战 → 只剩 `棋局设置` + `界面与操作`；人机/自对弈 → 只显示真正用到的引擎组。
3. **放墙改为全程鼠标**（`games/quoridor/view.py`）：
   删掉 `ViewState.placing`、放墙朝向、W/H/V 快捷键与"放墙/横墙/竖墙"按钮。
   新增"鼠标意图"判定：取鼠标分数坐标到最近网格线的距离，
   `min(dist_v, dist_h) <= EDGE_ZONE(0.26)` 就是放墙（朝向按更近的那条线，
   在交点附近两者都近时优先给**能放**的朝向），否则就是走子。
   还加了兜底：在该位置放不下墙、而底下格子是合法落点时，点击退化为走子。
   棋盘 HUD 左上角实时显示悬停意图（"点击放置横墙" / "横墙不可放" / "点击走子"）。
4. **折叠箭头改用绘制三角形**：`▶`（U+25B6）在微软雅黑里缺字，显示成豆腐块。
   只在 `Minimax 参数` 首行出现过 `▶`，`▼`/`▲` 是正常的。
5. **启用 git**：`git init` + `.gitattributes`（统一 LF）+ 首个提交 `49e61b9`（64 文件）。
   `.gitignore` 补上 `.workbuddy/artifacts/`；`.workbuddy/memory/` 纳入版本控制。

测试增至 124 项。

## 第四轮：放墙提示细化 + 侧栏布局 + 数值直接输入

1. **四个格子的公共交点不再提示放墙**（`games/quoridor/view.py`）：
   原来在交点附近会按"更近的那条线"猜朝向，鼠标一抖就在横/竖之间跳。
   新增 `CORNER_ZONE = 0.14`：`max(dv, dh) <= CORNER_ZONE` 时**不给任何放墙提示**，
   把鼠标往任一边挪一点才出现提示。同时删掉了原来的"两个朝向优先取合法那个"逻辑
   （它也是抖动的来源之一）。
2. **刚放下的墙不重复提示**：`_just_placed_wall` + `JUST_PLACED_RADIUS(0.75 格)`。
   放完墙鼠标还停在原地，以前会立刻显示"此墙不可放"的红色提示，很吵。
3. **双方信息移到侧栏头部固定**（`ui/sidebar.py`）：`HEADER_H` 122 → 178，
   玩家行放在 `PLAYERS_Y`，不再进滚动流 —— 滚动参数时墙数和轮到谁始终可见。
4. **数值参数可点击输入**（`ui/widgets/controls.py` + `ui/sidebar.py`）：
   `Slider.value_box` 点一下进入编辑态，支持数字/小数点（整数参数不接受小数点）、
   退格、回车或 Tab 确认、Esc 取消、点别处确认。手输只做 min/max 裁剪，**不按步长取整**
   （否则输 8 会被吸到 7）。
   关键点：`Sidebar.handle_key()` 在编辑时**接管全部键盘事件**并返回 True，
   主窗口收到 True 就不再走快捷键 —— 否则 Esc 会退出游戏、N/U/R 会误触发。
5. 测试重构：新增 `tests/ui/conftest.py`（`make_window` 夹具）与 `tests/ui/helpers.py`
   （鼠标/键盘模拟），新增 `tests/ui/test_interaction.py`。测试 124 → 138 项。

顺带核实：`Settings.set_volatile()` 确实能防止命令行覆盖落盘（直接跑命令 + 比对文件 md5 验证过），
pytest 也不会污染真实 `config/settings.json`（跑完 md5 不变）。
