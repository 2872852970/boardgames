## 修复：双击 boardgames.bat 启动不了（`No module named 'boardgames'`）

### 现象
bash / PowerShell 里 `uv run boardgames` 有的能跑有的不能；**双击 bat 必失败**。
症状是 `ModuleNotFoundError: No module named 'boardgames'`，或黑窗口一闪而过。

### 根因（中文路径 + editable 安装的 .pth 编码）
1. 项目在 `C:\Users\Admin\WorkBuddy\棋类游戏`（**含中文**）下。
2. uv 把本项目 editable 装进 `.venv`，生成
   `.venv\Lib\site-packages\_editable_impl_boardgames.pth`，内容是一行 **UTF-8** 的
   `C:\Users\Admin\WorkBuddy\棋类游戏\src`。
3. Python 的 `site.py` 在 Windows 上读 `.pth` 用 **系统 ANSI 编码（GBK/936）**
   → 解出乱码路径 → 目录不存在 → `site.addsitedir` **静默忽略** → `src` 不在 `sys.path`。
4. 于是 import 失败。**git bash 下 locale 不同碰巧能跑，cmd.exe（双击）必挂**。

验证对照（PowerShell 里）：
- 不设变量 → `ModuleNotFoundError`，exit 1
- `$env:PYTHONUTF8=1` → `OK ...\src\boardgames\__init__.py`

**解法：`PYTHONUTF8=1`**（PEP 540 UTF-8 模式，`.pth` 改按 UTF-8 读）。
`PYTHONPATH=<repo>\src` 作第二层兜底。

### `boardgames.bat` 重写
- `cd /d "%~dp0"` → `where uv` 检查（缺 uv 时给安装链接）→ `set PYTHONUTF8=1` +
  `set PYTHONPATH=%~dp0src;%PYTHONPATH%` → `uv run python -m boardgames.app %*`
  （用 `-m` 而非 console script，少走一层 launcher）→ 失败时 `pause` 让人看清错误。
- **编码：UTF-8 无 BOM，正文纯 ASCII**（用户要求 UTF-8 保存）。
- **不要 `chcp 65001`**：实测在禁用 ConPTY 的终端里**挂起 5 分钟以上**；
  且 cmd 用系统代码页解 `.bat`，非 ASCII 字节一律乱码。中文说明移到 README / USAGE。
- `.gitattributes` 加 `*.bat text eol=crlf`（纯 LF 在部分 Windows 上解析异常）。
- 实测真跑：`& .\boardgames.bat --offscreen --frames 3 --scene lobby` → exit 0，无乱码噪音。

### 诊断手法（值得复用）
同一条命令在 **bash 与 PowerShell 里跑出不同结果** 时，先别猜 ——
在两个环境里各跑 `uv run python -c "import sys; [print(p) for p in sys.path]"` 对比
`sys.path`，差异一眼可见（此处：`site-packages` 都在，但只有 bash 下有 `src`）。
进而怀疑"`.pth` 里的路径被解错了"，用 `PYTHONUTF8=1` 一验即中。

## 新增两个棋类：点格棋（dotsboxes）+ 播棋（mancala）

按 `docs/ADDING_A_GAME.md` 全流程接了两个新棋类，注册进大厅后**零改动**复用侧栏/主题/
AI 调度/悔棋/规则浮层。每个棋类 6 个文件 + 3 处注册 + 侧栏参数 + 契约测试，一次通过。

### 点格棋（Dots and Boxes）
- `games/dotsboxes/`：state / move / heuristic / rules / view。默认 6×6 点 = 5×5 格。
- 状态：`h_edges`/`v_edges` 存 **0空/1玩家1/2玩家2**（谁画的，用于双方边颜色区分），
  `boxes` 存格归属，`scores` 冗余。着法 `EdgeMove(orient,row,col,player)`。
- 核心规则：画满一格的第四条边即占格，**同玩家继续（额外回合）**；`current` 只在没封格时翻转。
- 侧栏参数 `dotsboxes_size`（3~9）。图标 `dotsboxes`（4×4 点阵 + 已画边 + 占领格）。

### 播棋（Mancala / Kalah）
- `games/mancala/`：state / move / heuristic / rules / view。2×6 坑 + 2 仓库。
- **播种方向（逆时针）**：玩家0 `0..5, store0, 11..6`；玩家1 `11..6, store1, 0..5`。
  `sow_path()` 是纯函数，rules 和 heuristic 共用 —— 第一版把玩家0方向写成
  `0..11, store0`（错），导致"落仓库额外回合""捕获"全部测错，修正后对。
- **平局终局**：`winner_player=None` 既可能是"没下完"也可能是"下完打平"。
  必须加 `over` 字段区分，`is_terminal` 判 `over`、`winner()` 仍返回 `winner_player`。
  漏了它，平局局面会继续生成着法（着法表空）→ MCTS rollout 抛 `RuntimeError`（"AI 突然不下棋"）。
- 侧栏参数 `mancala_pits`(3~8) / `mancala_seeds`(1~8)。图标 `mancala`（坑 + 仓库 + 种子圆点）。

### 顺带修的框架级问题：minimax 支持"额外回合"
`negamax`/`root_search` 原本假设每步换边（`score = -value`）。点格棋封格、播棋落己方仓库
都是**同玩家继续**，不换边，旧逻辑会把额外回合的价值错误取反 → 点格棋 depth<5 选不出封口边。
修法：检测 `child.current_player == player`，是则**不取反**、alpha/beta 不换边。
对无额外回合的棋类零影响（它们每步必换边）。

## 播棋几何一致性修复（本轮验证时发现）

播种验证截图时发现视图几何与规则层不一致，已修：

- **回路不变量**：`sow_path` 的槽位回路是 `0..p-1 → 仓库0 → 2p-1..p → (回 0)`，
  屏幕上要连续绕圈，**仓库 0 必须在右端**、仓库 1 在左端，且顶排显示必须
  `_col_to_pit(1,col)=p+col`（左→右 = pit p..2p-1）。之前仓库画反 + 顶排映射
  反转，种子预览/动画会从"下排最右"瞬移到"最左仓库"。
- **`opposite()` 原来是错的**：`2p-1-k` 的配对与任何平面棋盘都不兼容（仓库会
  被迫夹在互为对面的两坑之间）。平面棋盘同列两坑下标差恒为 p，改为
  `(pit + p) % (2p)`；捕获真正符合规则文案的"正对面"。改了 3 个捕获测试的
  局面构造（对面坑下标变了）。
- **教训**：规则层的抽象坑序和视图的屏幕坐标必须共享同一套"回路不变量"，
  加新棋类时先写下"绕一圈的槽位顺序 + 相邻关系"，再定显示映射。
- `out/verify_shots.py` 是一次性验证脚本（拍停靠规则面板 / 播种动画中帧），
  注意 `build_window(window_size=...)` 要传 **tuple**，传 "WxH" 字符串会得到
  1x1 黑窗。

## 修点格棋鼠标错位 + 引擎参数搬到「设置」+ 侧栏/浮层重排

### 1. 点格棋"鼠标位置和画出来的线差半格"
先把几何逐像素对过：`_draw_edges` / `_draw_boxes` / `_draw_points` 与
`point_pos` 完全一致（截图里圆点行中心 145.5、橙线中心 146），**渲染本身没偏**。
真正的问题在**命中测试**：

- 旧 `_edge_at` 用"`round` 取整 + 沿边/垂直各 ±0.42 格的窄带"，
  格子正中间是**死区**（点不动任何东西）→ 玩家看到的就是"指着线、亮的却是旁边那条"；
- 更硬的 bug：`_edge_at` 返回的 `EdgeMove` **写死了 `player=0`**，而
  `handle_motion` 拿它去问 `game.is_legal`，`is_legal` 校验
  `move.player == state.current` → **轮到玩家 2 时预览永远不亮**。

改法：`_edge_at` 改成**最近邻（Voronoi）**——只算两条候选（最近的水平边 / 最近的垂直边），
比"到线段的欧氏距离"取小的；棋盘内处处能命中。另外：

- 返回 `(orient, row, col)`，着法由调用方用 `state.current` 造（修掉上面那个 bug）；
- 未画的边画成**浅色格线轨道**（`_draw_slots`，受 `show_hints` 控制）→ 哪里能画一眼可见；
- 加可选钩子 `clear_hover()`，鼠标离开棋盘收掉幽灵线；
- 加 `idle_hint()`（左上角胶囊不再显示四子棋的"投子"）。

`tests/ui/test_dotsboxes_view.py`（11 例）锁住：所有边中点自对应、棋盘内无死区、
命中即最近、两个玩家的悬停、点击处的像素有该玩家色且**半格之外没有**。

### 2. `p1_type` / `p2_type` 存不住 "human"（真隐患）
`ParamSpec(choices=AI_TYPES)` + `coerce()` 未知值回落到默认值 ⇒ 写 `"human"` 被静默
改写成 `"minimax"`/`"mcts"`。后果：**选「我执 玩家 2」等于没选**，
下拉显示的和真正跑起来的 AI 必然对不上（用户报的"下拉和实际 AI 不符"）。
新增 `ParamSpec.accepts`（校验允许值 ⊃ 界面候选），`p1_type`/`p2_type` 用它放开 `human`。

### 3. 两个虚拟控件开局不同步

下拉却写着 Minimax。`Sidebar._build()` 末尾补 `sync_from_settings()`；
`_on_mode_change()` 也在改完 p1/p2_type 后 sync 一次。

## 第二轮 UI 改造：先手移除 / 设置区稳定 / 每项 ↺ / 模式锁定 / 昆虫棋视角

  `session._build_game` 不再传参、`_resolve_first_player()` 删除；

### R3 每一项设置都能恢复初始值
- `ValueWidget` 长出通用能力：`default` / `on_reset` / `has_reset` / `reset_rect` /
  `handle_reset()` / `draw_reset()`。**四个控件共用一份实现**。

- 关键坑 2：布局常量级稳定 —— 每个控件的右端元素（`value_box` / `_switch` / `_box`）都让出

- 关键坑 3：`reset()` 里 `on_reset()` 只管写回设置，**必须再 `set_value_silently(default)`**
  同步自己，否则"设置里是 4、界面还写 7、↺ 还亮着"。
- 关键坑 4：图标**不能用 `pygame.draw.arc`**（角度与视觉方向相反，只画出半个圈像乱码），
  改成采样折线 + 端点切线箭头。
- 浮层右上角「全部恢复默认」：只重置 `_widget_applicable` 的项（别的棋类的调参不许被连坐），
  点完立刻 `_refresh_reset_all()`（不等下一帧），无改动时按钮变灰。

- `ValueWidget` 长出通用能力：`default` / `on_reset` / `has_reset` / `reset_rect` /
  `handle_reset()` / `draw_reset()`。**四个控件共用一份实现**。
- 关键坑 1：↺ 落在行右端，而滑块的拖拽区覆盖整行 → 各控件 `handle_event` 里**必须先调
  `handle_reset()`**；下拉展开时要让它先接管（`not self.open` 才认 ↺）。
- 关键坑 2：布局常量级稳定 —— 每个控件的右端元素（`value_box` / `_switch` / `_box`）都让出
  `RESET_W = 26`，与 `has_reset` 无关，否则 ↺ 一亮同行元素就左右跳。
- 关键坑 3：`reset()` 里 `on_reset()` 只管写回设置，**必须再 `set_value_silently(default)`**
  同步自己，否则"设置里是 4、界面还写 7、↺ 还亮着"。
- 关键坑 4：图标**不能用 `pygame.draw.arc`**（角度与视觉方向相反，只画出半个圈像乱码），
  改成采样折线 + 端点切线箭头。
- 浮层右上角「全部恢复默认」：只重置 `_widget_applicable` 的项（别的棋类的调参不许被连坐），
  点完立刻 `_refresh_reset_all()`（不等下一帧），无改动时按钮变灰。

### R4 三种模式只在开局前可选
`Sidebar.update()` 里 `_mode_widget.enabled = not locked`（`locked = status.started`），
锁定时压一层 `(*BG_ALT, 150)` 蒙版。模式下方**常驻一行 16px 提示**（`MODE_HINT_Y = 97`）：
未开局"三种模式在对局开始后锁定"，已开局"已开始 · 开新局可改" —— 常驻是为了不跳布局。
`PLAYERS_Y` 100 → 120、`HEADER_H` 196 → 226。

### R5 昆虫棋人机对战：手牌条钉在我方
- 框架侧：`ViewState.pov_player`（可选字段）+ `MatchScene._pov_player()`（pve 返回人类那一方，
  其余模式 None = 跟随当前行动方）。
- 视图侧：`HiveView._hand_player(view)` 决定手牌条画谁；`_drop_foreign_selection()`
  在 pov != current 时清掉残留的选择 / 落点表并把 `_refreshed` 置真；
  `draw()` 里落点提示与选中环都要求 `interactive and mine`；`handle_click()` 对
  pov != current 直接返回 None（不依赖场景那层守卫）。
- 双人同屏 / 自对弈行为不变。余量胶囊按用户选择保留。

### 顺带修的观感问题
